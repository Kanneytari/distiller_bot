# Distiller Bot

Telegram-бот для домашних винокуров: рецепты, калькуляторы, профиль оборудования и ведение истории напитков.

## Идея

Distiller Bot — не просто набор отдельных калькуляторов, а персональный помощник винокура, который помнит оборудование пользователя, его рецепты, текущие процессы и результаты прошлых напитков.

Основная идея продукта — связать все функции между собой:

**рецепт → оборудование → напиток → замеры и расчёты → результат → история**

Пользователь один раз указывает своё оборудование, после чего бот использует эти данные в рецептах, калькуляторах и при ведении напитков.

## Основные принципы интерфейса

- Основное управление осуществляется через **inline-кнопки**.
- Меню должно быть максимально простым и интуитивным.
- Минимум уровней вложенности.
- Основные действия должны выполняться за 1–2 нажатия.
- На каждом экране должно быть очевидно, что пользователь может сделать дальше.
- Не показывать лишние параметры до тех пор, пока они не нужны.
- Не спрашивать повторно данные, которые бот уже знает.
- Тексты должны быть короткими, понятными и удобными для чтения с телефона.
- Профессиональные термины использовать только там, где они действительно полезны.

Предварительная структура главного меню:

- 🥃 **Напитки**
- 📖 **Рецепты**
- 🧮 **Калькуляторы**
- ⚙️ **Оборудование**

Дополнительные функции должны открываться внутри этих разделов, а не раздувать главное меню.

---

## 🥃 Напитки

Центральный раздел бота. Здесь пользователь ведёт текущие и завершённые напитки от начала процесса до итогового результата.

Для каждого напитка бот хранит:

- название;
- используемый рецепт;
- дату начала;
- текущий этап;
- исходное сырьё и объёмы;
- замеры;
- крепость и объём продукта на разных этапах;
- заметки пользователя;
- историю действий;
- итоговый результат;
- дегустационную оценку.

Пример жизненного цикла:

**подготовка → брожение → перегон → разбавление → выдержка → готово**

Набор этапов не должен быть жёстко одинаковым для всех типов напитков.

### Замеры

Пользователь может добавлять к напитку измерения, например:

- температуру;
- плотность;
- крепость;
- объём;
- произвольную заметку.

Замеры сохраняются в хронологическом порядке и формируют журнал конкретного напитка.

### Напоминания

Из карточки напитка можно создать напоминание о следующем действии, например:

- проверить плотность;
- выполнить повторный замер;
- проверить выдержку;
- вернуться к напитку через заданное время.

## 📖 Рецепты

Бот содержит готовые рецепты и позволяет пользователю создавать собственные.

Основные возможности:

- просмотр каталога рецептов;
- категории рецептов;
- поиск и фильтрация;
- сохранение рецепта себе;
- создание собственного рецепта;
- копирование существующего рецепта с последующим редактированием;
- пересчёт ингредиентов под нужный объём;
- запуск нового напитка непосредственно из рецепта.

Рецепт может содержать:

- название и описание;
- тип напитка;
- список ингредиентов и их количество;
- базовый объём;
- основные этапы;
- ориентировочные сроки;
- дополнительные заметки.

### Связь с оборудованием

Если пользователь уже заполнил профиль оборудования, бот должен учитывать его автоматически.

Например, если рецепт рассчитан на 50 л, а рабочий объём оборудования пользователя — 30 л, бот может предложить пересчитать рецепт под 30 л.

### Связь с напитками

Кнопка **«Начать»** создаёт новый напиток на основе рецепта. Все исходные параметры рецепта копируются в него, после чего пользователь ведёт уже конкретный процесс и может фиксировать фактические значения.

---

## 🧮 Калькуляторы

Набор наиболее востребованных расчётов для винокура.

На первом этапе планируются:

- разбавление продукта до нужной крепости;
- смешивание жидкостей разной крепости;
- расчёт абсолютного спирта;
- температурная коррекция показаний спиртометра;
- пересчёт рецепта под другой объём;
- расчёт ориентировочного выхода;
- расчёт количества готовых бутылок из имеющегося объёма.

Калькуляторы должны работать в двух режимах:

1. **Быстрый расчёт** — пользователь самостоятельно вводит значения.
2. **Расчёт для напитка** — исходные данные автоматически подставляются из выбранного напитка.

Например, если в текущем напитке уже сохранено `4.3 л · 76%`, при открытии калькулятора разбавления эти значения не нужно вводить повторно.

---

## ⚙️ Оборудование

Пользователь один раз создаёт профиль своего оборудования, после чего эти параметры используются в других разделах бота.

В профиле можно хранить, например:

### Перегонное оборудование

- объём куба;
- рекомендуемый рабочий объём;
- тип аппарата;
- мощность нагрева;
- параметры колонны и других используемых компонентов.

### Ёмкости

- ферментеры;
- ёмкости для хранения;
- ёмкости для выдержки.

Необязательно заставлять пользователя заполнять все параметры. Достаточно тех данных, которые действительно используются ботом.

---

## 📊 История и статистика

История формируется автоматически на основе завершённых напитков.

В дальнейшем бот сможет показывать:

- количество завершённых напитков;
- историю конкретного рецепта;
- фактический выход;
- продолжительность процессов;
- дегустационные оценки;
- сравнение повторных приготовлений одного рецепта.

Главная ценность статистики — возможность ответить на вопрос: **«Что я делал в прошлый раз и какой результат получил?»**

---

## ⭐ Дегустационные заметки

Для готового напитка пользователь может сохранить собственную оценку результата.

Например:

- аромат;
- вкус;
- послевкусие;
- общую оценку;
- текстовые заметки.

Эти данные связываются с конкретным напитком и рецептом, чтобы пользователь мог сравнивать результаты повторных приготовлений.

---

## 📦 Запасы

Дополнительный раздел, который можно развивать после основного MVP.

Пользователь сможет учитывать:

- сырьё;
- дрожжи;
- расходные материалы;
- дуб;
- бутылки и тару;
- другие запасы.

В дальнейшем рецепты смогут показывать, какие ингредиенты уже есть в наличии, а каких не хватает.

# MVP

Первая версия не должна пытаться реализовать всё сразу.

Приоритет MVP:

1. Telegram-пользователи.
2. Простое inline-меню.
3. Профиль оборудования.
4. Рецепты.
5. Создание напитка из рецепта или вручную.
6. Этапы напитка.
7. Замеры и заметки.
8. Базовые калькуляторы.
9. История завершённых напитков.
10. Простые напоминания.

Запасы, расширенную аналитику, социальные функции, экспорт и AI-помощника следует рассматривать только после того, как основной сценарий станет удобным и стабильным.

## Главный пользовательский сценарий

```text
Первый запуск
    ↓
Добавить оборудование
    ↓
Выбрать рецепт
    ↓
Автоматически пересчитать его под своё оборудование
    ↓
Начать напиток
    ↓
Фиксировать этапы и замеры
    ↓
Использовать калькуляторы с автоматически подставленными данными
    ↓
Завершить напиток
    ↓
Сохранить результат и оценку
    ↓
В следующий раз повторить или скорректировать рецепт
```

- **Python**
- **aiogram 3**
- **PostgreSQL**
- **SQLAlchemy 2**
- **Alembic**
- **asyncpg**

На старте не добавляем дополнительные инфраструктурные компоненты без реальной необходимости. Архитектура должна оставаться простой, понятной и пригодной для постепенного расширения.
