# Distiller Bot

Telegram-бот для домашних винокуров: рецепты, калькуляторы, профиль оборудования и ведение истории напитков.

## Идея

Distiller Bot — персональный помощник винокура, который можно подключить **на любом этапе производства любого напитка**.

Бот не должен навязывать пользователю собственный технологический процесс, конкретный рецепт или обязательную последовательность действий. Пользователь может начать работу с ботом тогда, когда ему это удобно: перед постановкой сырья, во время брожения, перед перегонкой, после перегонки, на этапе разбавления, выдержки или уже с готовым продуктом.

Рецепты, оборудование, калькуляторы и журнал — независимые инструменты, которые становятся полезнее, когда пользователь связывает их между собой, но такая связь никогда не является обязательной.

Примеры допустимых сценариев:

- найти рецепт и начать новый процесс;
- создать свой процесс полностью с нуля;
- добавить уже идущий процесс сразу на текущем этапе;
- вести напиток без какого-либо рецепта;
- пользоваться только калькуляторами;
- сохранить оборудование и использовать его в расчётах;
- вести только замеры и заметки;
- добавить уже готовый напиток в историю.

Если пользователь хочет связать всё вместе, бот может использовать такую цепочку:

**рецепт → оборудование → напиток → замеры и расчёты → результат → история**

Но это только удобный сценарий, а не обязательная модель работы.

## Основные продуктовые принципы

- **Свободный вход в процесс.** Пользователь начинает с любого этапа, не создавая предыдущие задним числом.
- **Рецепт необязателен.** Любой напиток можно вести полностью вручную.
- **Этапы не должны быть жёсткими.** Бот предлагает типовые варианты, но пользователь может выбрать другой этап или задать свой.
- **Инструменты независимы.** Калькулятором можно пользоваться без напитка, рецептом — без запуска процесса, оборудованием — только для расчётов.
- **Контекст — это удобство, а не ограничение.** Если бот знает напиток, оборудование или предыдущие замеры, он подставляет их автоматически. Если не знает — позволяет ввести данные вручную.
- **Никакой обязательной “правильной технологии”.** Бот помогает считать, хранить данные и организовывать процесс, но не заставляет пользователя работать по встроенной схеме.

## Основные принципы интерфейса

- Основное управление осуществляется через **inline-кнопки**.
- Меню должно быть максимально простым и интуитивным.
- Минимум уровней вложенности.
- Основные действия должны выполняться за 1–2 нажатия.
- На каждом экране должно быть очевидно, что пользователь может сделать дальше.
- Не показывать лишние параметры до тех пор, пока они не нужны.
- Не спрашивать повторно данные, которые бот уже знает.
- Всегда оставлять возможность ввести значение вручную, если готовый вариант не подходит.
- Тексты должны быть короткими, понятными и удобными для чтения с телефона.
- Профессиональные термины использовать только там, где они действительно полезны.

Предварительная структура главного меню:

- 🥃 **Напитки**
- 📖 **Рецепты**
- 🧮 **Калькуляторы**
- ⚙️ **Оборудование**

Дополнительные функции должны открываться внутри этих разделов, а не раздувать главное меню.

Подробная карта экранов и навигации: [`docs/UX_FLOW.md`](docs/UX_FLOW.md).

## 🥃 Напитки

Центральный раздел для тех пользователей, которые хотят вести историю своих процессов и результатов.

Под «напитком» понимается пользовательская рабочая запись о конкретном процессе или продукте. Она может быть создана **на любом этапе**. Пользователь не обязан начинать с сырья или брожения и не обязан заполнять предыдущие этапы.

Например, можно сразу создать:

- брагу, которая уже бродит;
- спирт-сырец перед второй перегонкой;
- дистиллят перед разбавлением;
- напиток, уже поставленный на выдержку;
- готовый продукт только для сохранения результата и дегустационных заметок.

Для напитка бот может хранить:

- название;
- необязательную связь с рецептом;
- дату добавления и, если известно, дату начала процесса;
- текущий этап;
- сырьё и объёмы, если пользователь хочет их сохранить;
- замеры;
- крепость и объём на разных этапах;
- заметки пользователя;
- историю действий;
- итоговый результат;
- дегустационную оценку.

Типовой жизненный цикл может выглядеть так:

**подготовка → брожение → перегон → разбавление → выдержка → готово**

Но это лишь подсказка. Набор этапов не должен быть обязательным или одинаковым для всех напитков.

### Замеры

Пользователь может добавлять к напитку измерения, например:

- температуру;
- плотность;
- крепость;
- объём;
- произвольную заметку.

Замеры сохраняются в хронологическом порядке и формируют журнал конкретного напитка.

### Напоминания

Из карточки напитка можно создать напоминание о любом следующем действии. Бот может предложить контекстные варианты, но пользователь всегда может написать собственный текст.

### История и результат

Пользователь может завершить напиток или сразу добавить уже готовый продукт. Результат сохраняется в истории независимо от того, велись ли предыдущие этапы внутри бота.

## 📖 Рецепты

Рецепты — полезный самостоятельный инструмент, но **не основа и не обязательное условие работы бота**.

В боте могут быть:

- базовые рецепты;
- сохранённые пользователем рецепты;
- собственные рецепты пользователя.

Рецепт содержит состав, пропорции, ориентировочные этапы и параметры процесса.

Его можно:

- просто посмотреть;
- сохранить;
- пересчитать под другой объём;
- адаптировать под оборудование;
- скопировать и изменить;
- использовать как основу нового напитка.

При этом любой напиток можно создавать и вести вообще без рецепта.

---

## 🧮 Калькуляторы

Калькуляторы — полностью самостоятельный раздел. Для их использования не нужно создавать напиток, рецепт или профиль оборудования.

Если контекст есть, бот может автоматически подставить известные параметры. Если контекста нет или пользователь не хочет его использовать — все значения вводятся вручную.

Базовый набор:

- разбавление спирта до нужной крепости;
- смешивание жидкостей разной крепости;
- расчёт абсолютного спирта;
- температурная поправка показаний спиртометра;
- ориентировочный расчёт выхода;
- пересчёт рецепта на другой объём;
- расчёт количества бутылок из готового объёма.

Калькулятор должен запрашивать только необходимые значения и сразу выдавать понятный результат.

---

## ⚙️ Оборудование

Профиль оборудования необязателен.

Пользователь может сохранить оборудование, чтобы бот автоматически использовал его параметры в рецептах и расчётах, но отсутствие профиля не должно блокировать никакую основную функцию.

Можно хранить:

- перегонный куб и его объём;
- ферментеры;
- колонну и основные параметры;
- тип и мощность нагрева;
- другое пользовательское оборудование.

Пользователь может иметь несколько единиц одного типа оборудования и при необходимости выбирать нужную.

---

## ⭐ Дегустационные заметки

Для готового напитка пользователь может сохранить собственную оценку:

- аромат;
- вкус;
- послевкусие;
- общую оценку;
- текстовую заметку.

Готовый напиток можно добавить сразу, даже если его производство ранее никак не велось в боте.

---

## 📦 Запасы

Перспективная функция после базового MVP.

Бот может учитывать домашние запасы сырья и расходников: солод, сахар, дрожжи, дуб, бутылки и т. п. В дальнейшем рецепты смогут показывать, чего не хватает, но использование запасов не должно становиться обязательным условием запуска процесса.

## MVP

Первая рабочая версия должна доказать, что бот полезен как набор связанных, но независимых инструментов.

В MVP входят:

1. профиль пользователя;
2. необязательный профиль оборудования;
3. создание напитка с любого этапа;
4. свободный выбор и изменение текущего этапа;
5. замеры и заметки;
6. необязательные рецепты;
7. базовые самостоятельные калькуляторы;
8. напоминания;
9. история завершённых напитков.

Ключевой критерий MVP: пользователь не должен столкнуться с ситуацией «бот не даёт мне это сделать, потому что я не начал процесс внутри бота».

После проверки этих сценариев можно постепенно добавлять статистику, дегустационные оценки, запасы, расширенные рецепты и другие возможности.

## Технологический стек

Стек MVP:

- Python 3.13;
- aiogram 3;
- SQLite;
- SQLAlchemy 2;
- aiosqlite.

SQLite хранит данные в одном локальном файле `distiller_bot.db`, который создаётся автоматически при запуске. Для локальной разработки не нужен отдельный сервер БД, пользователь БД или ручное применение миграций.

Главная техническая цель — сохранить архитектуру простой и понятной. Более тяжёлые компоненты добавляются только тогда, когда появляется реальная необходимость.
