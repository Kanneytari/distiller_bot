# Distiller Bot

Telegram-бот для домашних винокуров: рецепты, калькуляторы, профиль оборудования и ведение истории напитков.

## Идея

Distiller Bot — не просто набор отдельных калькуляторов, а персональный помощник винокура, который помнит оборудование пользователя, его рецепты, текущие процессы и результаты прошлых напитков.

Основная идея продукта — связать все функции между собой:

**рецепт → оборудование → напиток → замеры и расчёты → результат → история**

Пользователь один раз указывает своё оборудование, после чего бот использует эти данные в рецептах, калькуляторах и при ведении напитков.

## Основные принципы интерфейса

- Основное управление осуществляется через **inline-кнопки**.
- Меню должно быть максимально простым и интуитивным.
- Минимум уровней вложенности.
- Основные действия должны выполняться за 1–2 нажатия.
- На каждом экране должно быть очевидно, что пользователь может сделать дальше.
- Не показывать лишние параметры до тех пор, пока они не нужны.
- Не спрашивать повторно данные, которые бот уже знает.
- Тексты должны быть короткими, понятными и удобными для чтения с телефона.
- Профессиональные термины использовать только там, где они действительно полезны.

Предварительная структура главного меню:

- 🥃 **Напитки**
- 📖 **Рецепты**
- 🧮 **Калькуляторы**
- ⚙️ **Оборудование**

Дополнительные функции должны открываться внутри этих разделов, а не раздувать главное меню.

Подробная карта экранов и навигации: [`docs/UX_FLOW.md`](docs/UX_FLOW.md).

## 🥃 Напитки

Центральный раздел бота. Здесь пользователь ведёт текущие и завершённые напитки от начала процесса до итогового результата.

Для каждого напитка бот хранит:

- название;
- используемый рецепт;
- дату начала;
- текущий этап;
- исходное сырьё и объёмы;
- замеры;
- крепость и объём продукта на разных этапах;
- заметки пользователя;
- историю действий;
- итоговый результат;
- дегустационную оценку.

Пример жизненного цикла:

**подготовка → брожение → перегон → разбавление → выдержка → готово**

Набор этапов не должен быть жёстко одинаковым для всех типов напитков.

### Замеры

Пользователь может добавлять к напитку измерения, например:

- температуру;
- плотность;
- крепость;
- объём;
- произвольную заметку.

Замеры сохраняются в хронологическом порядке и формируют журнал конкретного напитка.

### Напоминания

Из карточки напитка можно создать напоминание о следующем действии, например:

- проверить плотность;
- выполнить повторный замер;
- проверить выдержку;
- перейти к следующему этапу.

### История и результат

После завершения напитка бот сохраняет фактический результат. В дальнейшем пользователь может сравнивать похожие напитки и повторять удачные варианты.

## 📖 Рецепты

В боте должны быть:

- базовые рецепты;
- сохранённые пользователем рецепты;
- собственные рецепты пользователя.

Рецепт содержит состав, пропорции, ориентировочные этапы и параметры процесса.

Главная особенность — рецепт можно адаптировать под оборудование пользователя. Например, если бот знает объём куба или ферментера, он предлагает пересчитать количества под подходящий объём.

Из карточки рецепта пользователь может:

- сохранить рецепт;
- пересчитать пропорции;
- начать новый напиток;
- создать свою копию и изменить её.

---

## 🧮 Калькуляторы

Калькуляторы должны быть простыми и быстрыми. По возможности бот автоматически подставляет известные параметры текущего напитка или оборудования.

Базовый набор:

- разбавление спирта до нужной крепости;
- смешивание жидкостей разной крепости;
- расчёт абсолютного спирта;
- температурная поправка показаний спиртометра;
- ориентировочный расчёт выхода;
- пересчёт рецепта на другой объём;
- расчёт количества бутылок из готового объёма.

Калькулятор должен запрашивать только необходимые значения и сразу выдавать понятный результат.

---

## ⚙️ Оборудование

Пользователь один раз создаёт профиль своего оборудования. Эти данные затем используются по всему боту.

Можно хранить:

- перегонный куб и его объём;
- ферментеры;
- колонну и основные параметры;
- тип и мощность нагрева;
- другое пользовательское оборудование.

Пользователь может иметь несколько единиц одного типа оборудования и выбирать нужную для конкретного процесса.

---

## ⭐ Дегустационные заметки

Для завершённого напитка пользователь может сохранить собственную оценку:

- аромат;
- вкус;
- послевкусие;
- общую оценку;
- текстовую заметку.

Это позволяет постепенно сформировать личную историю рецептов и результатов.

---

## 📦 Запасы

Перспективная функция после базового MVP.

Бот может учитывать домашние запасы сырья и расходников: солод, сахар, дрожжи, дуб, бутылки и т. п. В дальнейшем рецепты смогут показывать, чего не хватает для запуска напитка.

---

## MVP

Первая рабочая версия должна сосредоточиться на основных сценариях и не пытаться реализовать всё сразу.

В MVP входят:

1. профиль пользователя;
2. профиль оборудования;
3. напитки и их текущий этап;
4. замеры и заметки;
5. рецепты;
6. базовые калькуляторы;
7. напоминания;
8. история завершённых напитков.

После проверки этих сценариев можно постепенно добавлять статистику, дегустационные оценки, запасы, расширенные рецепты и другие возможности.

## Технологический стек

Предварительный стек:

- Python 3.13;
- aiogram 3;
- PostgreSQL;
- SQLAlchemy 2;
- Alembic;
- asyncpg.

Главная техническая цель — сохранить архитектуру простой и понятной. Новые компоненты вроде Redis, Celery или отдельных сервисов добавляются только тогда, когда появляется реальная необходимость.
