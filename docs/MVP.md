# MVP Distiller Bot

Цель первой версии — дать винокуру несколько действительно полезных инструментов в одном Telegram-боте, не заставляя его работать по встроенному сценарию.

Пользователь может открыть бот на любом этапе производства, использовать только нужную функцию и не заполнять данные, которые ему сейчас не нужны.

## Что должен уметь MVP

### 1. Первый запуск

- `/start` создаёт профиль пользователя автоматически.
- Никакой обязательной регистрации или длинного опроса.
- Пользователь сразу попадает в простое главное меню.
- Добавление оборудования предлагается как полезная возможность, но не является обязательным.

Главное меню:

- 🥃 Напитки
- 📖 Рецепты
- 🧮 Калькуляторы
- ⚙️ Оборудование

Основное управление после `/start` — inline-кнопками.

---

## 2. Напитки

«Напиток» — пользовательская рабочая запись о конкретном продукте или производственном процессе.

Запись можно создать на любом этапе. Пользователь не обязан начинать с рецепта, сырья или брожения.

При создании достаточно:

1. указать название;
2. выбрать текущий этап или написать свой.

Остальные данные добавляются позже по необходимости.

Типовые этапы, которые бот может предложить:

- подготовка;
- брожение;
- перегонка;
- разбавление;
- выдержка;
- готово;
- свой этап.

Это не жёсткий workflow. Пользователь может выбрать любой этап в любой момент.

Для напитка MVP хранит:

- название;
- текущий этап;
- дату создания;
- необязательную дату начала процесса;
- необязательную связь с рецептом;
- необязательную связь с оборудованием;
- замеры;
- заметки;
- историю изменения этапов;
- напоминания;
- статус: активный / завершённый.

### Замеры

В MVP поддерживаются:

- температура;
- плотность;
- крепость;
- объём;
- произвольный числовой замер;
- текстовая заметка.

Каждый замер сохраняется с датой и временем.

### Журнал

Все важные действия отображаются одной хронологией:

- создан напиток;
- изменён этап;
- добавлен замер;
- добавлена заметка;
- сохранён результат калькулятора;
- завершён процесс.

---

## 3. Рецепты

Рецепты — отдельный полезный инструмент, а не обязательная основа работы бота.

В MVP пользователь может:

- смотреть встроенные рецепты;
- искать и открывать рецепт;
- сохранять рецепт себе;
- создавать собственный рецепт;
- изменять собственный рецепт;
- пересчитывать рецепт на другой объём;
- при желании создать напиток на основе рецепта.

Напиток, созданный по рецепту, остаётся обычным свободным напитком: пользователь может менять этапы, параметры и процесс как угодно.

Минимальная структура рецепта:

- название;
- краткое описание;
- базовый объём;
- ингредиенты;
- краткие шаги;
- категория.

---

## 4. Калькуляторы

Калькуляторами можно пользоваться полностью независимо от напитков и рецептов.

MVP-калькуляторы:

1. Разбавление спирта до заданной крепости.
2. Смешивание двух жидкостей разной крепости.
3. Абсолютный спирт.
4. Температурная поправка показаний спиртометра.
5. Пересчёт рецепта на другой объём.

Основной UX-принцип:

**один вопрос → одно значение → следующий вопрос → результат**.

Не использовать большие формы.

Если бот уже знает нужные параметры из выбранного напитка, он предлагает подставить их автоматически.

Пользователь всегда может выбрать ручной ввод.

После расчёта, связанного с напитком, можно сохранить результат в его журнал.

---

## 5. Оборудование

Пользователь может сохранить своё оборудование один раз и затем использовать его как контекст в рецептах и расчётах.

MVP-типы:

- перегонный куб;
- ферментер;
- колонна;
- нагрев;
- другое.

Оборудование необязательно.

Для каждой единицы достаточно хранить:

- пользовательское название;
- тип;
- основные параметры;
- необязательные дополнительные параметры.

Пользователь может иметь несколько единиц оборудования одного типа.

---

## 6. Напоминания

Напоминание создаётся из контекста напитка.

Минимально нужны:

- текст напоминания;
- дата и время;
- связь с напитком;
- статус выполнено / ожидает.

Бот предлагает быстрые варианты времени и позволяет указать своё.

---

# Что НЕ входит в первый MVP

Не реализуем до проверки основных сценариев:

- AI-ассистента;
- социальные функции;
- публичные профили;
- рейтинги рецептов;
- комментарии;
- маркетплейс рецептов;
- складской учёт;
- автоматическое списание ингредиентов;
- расширенную аналитику;
- сложные графики;
- экспорт PDF/Excel;
- QR-коды;
- фотографии и распознавание приборов;
- совместный доступ к напитку;
- сложную дегустационную систему;
- десятки типов оборудования;
- обязательные технологические цепочки.

Эти функции можно добавлять позже без изменения базовой модели продукта.

---

# Критерий готовности MVP

MVP можно считать рабочим, если новый пользователь без инструкции способен:

1. запустить бота;
2. воспользоваться калькулятором без предварительной настройки;
3. добавить своё оборудование;
4. создать напиток на произвольном этапе;
5. добавить к нему замер и заметку;
6. изменить этап;
7. поставить напоминание;
8. открыть рецепт;
9. пересчитать его под нужный объём;
10. при желании создать напиток из рецепта;
11. завершить напиток и позже найти его в истории.

Если для выполнения этих действий пользователю приходится понимать внутреннюю модель бота или заполнять ненужные поля — UX MVP спроектирован неправильно.
