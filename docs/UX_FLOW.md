# UX Flow

Карта экранов и навигации Distiller Bot.

Цель интерфейса — сделать бота понятным без инструкций и полезным независимо от того, на каком этапе производства находится пользователь.

Ключевой принцип: **бот подключается к процессу пользователя, а не заставляет пользователя подстраивать процесс под бота**.

---

# 1. Общие UX-принципы

1. Всё основное управление — через inline-кнопки.
2. Главное меню содержит только четыре раздела:
   - 🥃 Напитки
   - 📖 Рецепты
   - 🧮 Калькуляторы
   - ⚙️ Оборудование
3. Основные действия доступны за 1–2 нажатия.
4. На одном экране желательно не больше 4–5 смысловых действий.
5. Дополнительные действия прячутся в «Ещё», если без этого экран становится перегруженным.
6. Бот не спрашивает повторно данные, которые уже знает.
7. Если можно предложить готовый вариант — бот предлагает его кнопкой вместо ручного ввода.
8. При этом пользователь всегда может выбрать «Другое» или ввести данные вручную.
9. Любой вложенный экран должен иметь понятный путь назад.
10. На большинстве экранов используются кнопки:
    - ← Назад
    - 🏠 Меню
11. После выполнения действия пользователь должен попадать в логичное состояние, а не в тупик.
12. Бот по возможности редактирует текущее сообщение вместо отправки большого количества новых сообщений.
13. Текст интерфейса короткий. Подробные пояснения показываются только по запросу.
14. Ни рецепт, ни оборудование, ни предыдущие этапы не являются обязательными для использования остальных функций.

## Свободный вход в процесс

Пользователь может начать пользоваться ботом на любом этапе:

- только выбирает, что приготовить;
- уже поставил брагу;
- получил спирт-сырец;
- готовится к повторной перегонке;
- разбавляет продукт;
- поставил напиток на выдержку;
- имеет уже готовый напиток;
- вообще не ведёт напитки и использует только калькуляторы.

Бот не должен требовать заполнения пропущенных этапов задним числом.

# 2. Первый запуск

## Экран 2.1 — Приветствие

Первый запуск не должен превращаться в регистрацию или обязательную настройку.

Пример:

> 🥃 Distiller Bot
>
> Расчёты, рецепты и журнал ваших напитков.
>
> Начните с того, что нужно вам сейчас.

Кнопки:

- 🚀 Начать

Переход:

`Начать → 3.1`

Оборудование не запрашивается обязательным шагом при первом запуске. Пользователь сам добавит его тогда, когда оно понадобится.

# 3. Главное меню

## Экран 3.1 — Главное меню

> 🥃 Distiller Bot
>
> Что хотите сделать?

Кнопки:

- 🥃 Напитки
- 📖 Рецепты
- 🧮 Калькуляторы
- ⚙️ Оборудование

Если есть активные процессы, можно коротко показать их над кнопками:

> Сейчас в работе:
> 🟡 Бурбон · брожение · 4 день
> 🪵 Кальвадос · выдержка · 38 дней

Не добавлять отдельные кнопки статистики, напоминаний, замеров, запасов и настроек в главное меню.

---

# 4. Напитки

Раздел «Напитки» — это журнал процессов пользователя. Запись можно создать на любом этапе, даже если предыдущие этапы проходили вне бота.

## Экран 4.1 — Список напитков

Если записей нет:

> 🥃 Напитки
>
> Здесь можно вести любой текущий процесс или сохранить уже готовый напиток.

Кнопки:

- ➕ Добавить напиток
- 📚 Завершённые
- 🏠 Меню

Если записи есть:

> 🥃 Напитки
>
> 🟡 Бурбон · брожение · 4 день
> 🔥 Спирт-сырец · перегонка
> 🪵 Кальвадос · выдержка · 38 дней

Кнопки:

- 🟡 Бурбон
- 🔥 Спирт-сырец
- 🪵 Кальвадос
- ➕ Добавить напиток
- 📚 Завершённые
- 🏠 Меню

При большом количестве записей используется пагинация.

## Экран 4.2 — Добавить напиток

Вместо обязательного выбора «по рецепту / с нуля» бот спрашивает, где пользователь находится сейчас.

> ➕ Добавить напиток
>
> На каком этапе вы сейчас?

Кнопки, например:

- 🌱 Подготовка
- 🫧 Брожение
- 🔥 Перегонка
- 💧 Разбавление
- 🪵 Выдержка
- ✅ Уже готов
- ✏️ Другой этап
- ← Назад

Это не технологическая схема, а быстрые варианты для интерфейса.

Пользователь может выбрать любой этап независимо от предыдущих.

## Экран 4.3 — Быстрое создание

После выбора этапа бот запрашивает только название.

> Как назовём эту запись?

Пользователь вводит название текстом.

После этого запись создаётся сразу и открывается её карточка.

Не требовать обязательно:

- категорию напитка;
- рецепт;
- ингредиенты;
- дату начала производства;
- оборудование;
- предыдущие этапы;
- стартовые замеры.

Все эти данные добавляются позже только при необходимости.

После создания можно ненавязчиво предложить:

- 📖 Привязать рецепт
- ⚙️ Указать оборудование
- ➕ Добавить замер
- Пропустить

Но ни один из этих шагов не обязателен.

## Экран 4.4 — Карточка напитка

Главный рабочий экран.

Пример:

> 🥃 Бурбон
>
> 🟡 Брожение · 4 день
>
> Последний замер:
> Плотность: 1.026 · сегодня

Основные кнопки:

- ➕ Замер
- 🔄 Изменить этап
- 🔔 Напомнить
- ⋯ Ещё
- ← Напитки
- 🏠 Меню

Если бот на основании контекста может предложить следующее действие, оно показывается как подсказка, но не как обязательный маршрут.

Например:

> Можно проверить плотность повторно.

## Экран 4.5 — Изменить этап

> 🔄 Текущий этап: брожение
>
> Что происходит сейчас?

Кнопки:

- 🔥 Перегонка
- 💧 Разбавление
- 🪵 Выдержка
- ✅ Готово
- ✏️ Другой этап
- ← Назад

Бот может показывать наиболее вероятные варианты первыми, но пользователь может перейти на любой этап.

Не требовать последовательного прохождения состояний.

## Экран 4.6 — Добавить замер

> ➕ Новый замер
>
> Что измерили?

Кнопки:

- 🌡 Температура
- 📏 Плотность
- 🥃 Крепость
- 💧 Объём
- 📝 Заметка
- ✏️ Другое
- ← Назад

После выбора бот запрашивает только значение и, если нужно, единицу измерения.

После сохранения:

> ✅ Замер сохранён

Кнопки:

- ➕ Ещё замер
- ← К напитку

## Экран 4.7 — Напоминание

> 🔔 Напомнить
>
> О чём напомнить?

Контекстные варианты могут зависеть от текущего этапа:

- Проверить плотность
- Проверить температуру
- Проверить выдержку
- ✏️ Свой текст

После выбора:

> Когда напомнить?

Кнопки:

- Завтра
- Через 3 дня
- Через неделю
- 📅 Другая дата
- ← Назад

## Экран 4.8 — «Ещё» в напитке

- 📋 Журнал
- 📖 Рецепт
- ⚙️ Оборудование
- ✏️ Изменить данные
- ⭐ Оценить результат
- 🗑 Удалить
- ← Назад

Если рецепт не привязан, пункт выглядит как `📖 Привязать рецепт`.

Если оборудование не указано — `⚙️ Указать оборудование`.

## Экран 4.9 — Журнал напитка

> 📋 Журнал · Бурбон
>
> 28 авг · Плотность 1.026
> 27 авг · Температура 24 °C
> 25 авг · Добавлен в бот на этапе брожения

Журнал отражает только то, что реально было сохранено пользователем. Бот не создаёт фиктивные предыдущие этапы.

Кнопки:

- ← Ранее
- Позже →
- ← К напитку

# 5. Рецепты

Рецепты — самостоятельный справочно-практический раздел, а не обязательная основа производства.

## Экран 5.1 — Рецепты

> 📖 Рецепты

Кнопки:

- ⭐ Мои
- 🔎 Найти рецепт
- 🌾 Зерновые
- 🍎 Фруктовые
- 🍬 Сахарные
- ➕ Свой рецепт
- 🏠 Меню

## Экран 5.2 — Список рецептов

Пример:

> 🌾 Зерновые рецепты

Кнопки:

- 🥃 Бурбон
- 🥃 Ржаной дистиллят
- 🥃 Пшеничный дистиллят
- → Далее
- ← Рецепты

## Экран 5.3 — Карточка рецепта

> 📖 Бурбон
>
> Базовый объём: 30 л
> Состав: …
> Основные этапы: …

Кнопки:

- 🧮 Пересчитать
- ⭐ Сохранить
- ▶️ Использовать как основу
- ⋯ Подробнее
- ← Назад

Формулировка «Использовать как основу» подчёркивает, что рецепт не является жёсткой программой процесса.

## Экран 5.4 — Пересчёт рецепта

Если оборудование известно, бот предлагает подходящий объём.

Если оборудования нет или пользователь хочет другое значение, объём вводится вручную.

После расчёта:

- ▶️ Создать напиток
- ⭐ Сохранить копию
- ← К рецепту

## Экран 5.5 — Создать напиток на основе рецепта

Бот копирует известные данные рецепта в новую запись, но пользователь может изменить их в дальнейшем.

Минимально:

> Создать напиток на основе «Бурбон»?

Кнопки:

- ✅ Создать
- 🧮 Изменить объём
- ← Назад

После создания открывается обычная карточка напитка. Дальше пользователь свободно ведёт процесс и не обязан следовать всем этапам рецепта.

## Экран 5.6 — Свой рецепт

Пользователь может создать собственный рецепт.

Минимально:

1. Название.
2. Базовый объём — необязательно.
3. Ингредиенты — необязательно.
4. Заметки/этапы — необязательно.

Разрешать сохранить даже частично заполненный рецепт.

# 6. Калькуляторы

Калькуляторы полностью независимы от остальных сущностей.

## Экран 6.1 — Калькуляторы

> 🧮 Калькуляторы
>
> Что нужно посчитать?

Кнопки:

- 💧 Разбавление
- 🥃 Смешивание крепостей
- 📐 Абсолютный спирт
- 🌡 Поправка спиртометра
- 📦 Выход продукта
- 📖 Пересчёт рецепта
- 🏠 Меню

Если функций становится много, использовать пагинацию или логические группы без глубокой вложенности.

## Экран 6.2 — Контекст калькулятора

По умолчанию калькулятор можно запустить сразу вручную.

Если есть подходящий текущий напиток, бот может дополнительно предложить:

> Использовать данные напитка?

Кнопки:

- 🥃 Бурбон
- ✏️ Ввести вручную
- ← Назад

Контекст ускоряет ввод, но не является обязательным.

## Экран 6.3 — Пример: разбавление

Без контекста:

> 💧 Разбавление
>
> Укажите объём.

Далее бот задаёт по одному вопросу: текущая крепость → желаемая крепость → результат.

С контекстом известные значения подставляются автоматически.

После результата, если выбран напиток:

- 💾 Сохранить в напиток
- 🔁 Новый расчёт
- ← Калькуляторы

Если расчёт был самостоятельным, кнопка сохранения в напиток не показывается.

Главный UX-принцип калькуляторов: **один вопрос → один ответ**, без больших форм.

# 7. Оборудование

Профиль оборудования — необязательное удобство.

## Экран 7.1 — Моё оборудование

Если оборудования нет:

> ⚙️ Оборудование
>
> Можно сохранить своё оборудование, чтобы быстрее выполнять расчёты и адаптировать рецепты.

Кнопки:

- ➕ Добавить
- 🏠 Меню

Никаких формулировок, создающих впечатление, что без оборудования бот работает не полностью.

Если оборудование есть:

> ⚙️ Моё оборудование
>
> 🛢 Куб · 37 л
> 🪣 Ферментер · 32 л
> 🔥 ТЭН · 3 кВт

Кнопки ведут в карточки конкретного оборудования.

## Экран 7.2 — Что добавить

> ➕ Оборудование
>
> Что хотите добавить?

Кнопки:

- 🛢 Перегонный куб
- 🪣 Ферментер
- 🧱 Колонна
- 🔥 Нагрев
- ✏️ Другое
- ← Назад

## Экран 7.3 — Добавление оборудования

Запрашиваются только параметры, которые реально используются ботом.

Дополнительные данные можно добавить позже.

## Экран 7.4 — Карточка оборудования

Пример:

> 🛢 Основной куб
>
> Объём: 37 л

Кнопки:

- ✏️ Изменить
- 🗑 Удалить
- ← Оборудование

# 8. Готовый напиток и история

## Экран 8.1 — Завершить или добавить готовый напиток

Пользователь может как довести существующую запись до состояния `Готово`, так и создать новую запись сразу на этапе `Уже готов`.

> ✅ Напиток готов
>
> Хотите сохранить оценку результата?

Кнопки:

- ⭐ Оценить
- ✅ Без оценки
- ← Назад

## Экран 8.2 — Короткая оценка

Для MVP достаточно общей оценки и необязательной заметки.

Не заставлять пользователя заполнять дегустационную анкету.

## Экран 8.3 — История

История открывается из раздела `Напитки`.

> 📚 Завершённые напитки
>
> ⭐ 5 · Бурбон · 24 августа
> ⭐ 4 · Кальвадос · 2 августа

В историю могут попадать как полностью проведённые через бот процессы, так и напитки, добавленные только на финальном этапе.

# 9. Навигация

## Главное правило

Пользователь не должен думать, какую Telegram-команду вводить.

`/start` — только техническая точка входа. Дальше управление происходит inline-кнопками.

## Кнопка «Назад»

Возвращает на один логический уровень вверх.

## Кнопка «Меню»

Всегда возвращает на главный экран.

## Отмена текстового ввода

Когда бот ждёт текст или число, остаётся кнопка:

- ❌ Отмена

Она возвращает пользователя в предыдущий логический экран.

---

# 10. Что не должно попадать в главное меню

- напоминания;
- замеры;
- журнал;
- история;
- дегустации;
- статистика;
- запасы;
- настройки конкретного напитка;
- пересчёты рецепта.

Эти функции открываются из соответствующего контекста.

---

# 11. Основные пользовательские сценарии MVP

## Сценарий A — пользоваться только калькулятором

`/start → Калькуляторы → Разбавление → Ввести значения → Результат`

Никакой профиль, рецепт или напиток не требуется.

## Сценарий B — добавить уже идущий процесс

`Напитки → Добавить напиток → Брожение → Название → Карточка напитка`

Предыдущие этапы не заполняются.

## Сценарий C — добавить процесс перед перегонкой

`Напитки → Добавить напиток → Перегонка → Название → Добавить объём/крепость при необходимости`

## Сценарий D — использовать рецепт

`Рецепты → Найти рецепт → Пересчитать при необходимости → Использовать как основу → Карточка напитка`

После этого рецепт ничего не блокирует и не диктует.

## Сценарий E — добавить замер

`Напитки → Напиток → Замер → Тип → Значение → Карточка напитка`

## Сценарий F — добавить уже готовый напиток

`Напитки → Добавить напиток → Уже готов → Название → Оценить / Пропустить → История`

## Сценарий G — использовать своё оборудование только в расчёте

`Оборудование → Добавить куб → Калькуляторы → Расчёт с подстановкой параметров`

Создавать напиток или рецепт для этого не нужно.

# 12. Границы MVP интерфейса

На первом этапе не нужны:

- сложные графики;
- социальные функции;
- рейтинги пользователей;
- публичные профили;
- маркетплейс рецептов;
- сложная система тегов;
- десятки типов оборудования;
- десятки параметров каждого устройства;
- обязательные технологические сценарии;
- AI-чат как центральный элемент интерфейса.

Главная проверка UX первой версии:

> Пользователь должен суметь открыть бот в любой момент своего реального процесса и за несколько действий получить пользу, не воссоздавая внутри бота всё, что происходило до этого.

Типовой полный сценарий всё ещё поддерживается:

**нашёл рецепт → адаптировал под оборудование → создал напиток → сохранил замеры → воспользовался расчётами → завершил → сохранил результат**

Но он является только одним из многих возможных сценариев, а не «правильным» способом использования бота.
